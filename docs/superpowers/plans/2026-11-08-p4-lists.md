# P4 — Lists Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Manage lists the way TickTick does. That means:
- creating, renaming, colouring, archiving, trashing and restoring lists;
- folders;
- sections (columns) inside a list;
- custom smart lists (filters);
- sort and group options per list;
- drag and drop to reorder tasks and lists and to move tasks between lists and sections.

**Architecture:** Same split as P3:
- **Shared** (`shared/.../lists/`): `ListActions`, `FilterRule` + `FilterEngine`, `SortOrder` helpers,
  and view options stored as `Preference` records (synced).
- **macOS**: sidebar context menus and sheets, a sort/group menu in the list toolbar, and
  `.draggable`/`.dropDestination` with stable string payloads.

The MCP tools for lists come at the end (spec §10a: list tools ship with P4).

**Spec:** §3 (priority 2), §6 (ProjectGroup, Project, Column, Filter, Preference), §11 (sidebar), §10a.

## Global Constraints

- Every edit goes through `ZenStore.update` / `put(value, base)`.
- Deleting a list = Trash (`trashedAt`) for the list and its tasks together. Restoring brings back the
  tasks trashed with it, using the same timestamp rule as task subtasks in P3. A permanent delete only
  happens from Trash, with a confirmation.
- The Inbox (`inbox`) cannot be renamed, archived or deleted.
- Sort orders follow TickTick's convention: `Long` values with gaps. A new item goes at the end
  (max + 2^32). Dropping between two items gives the midpoint. When there is no gap left, the list is
  renumbered in one transaction.
- Filters are a JSON rule stored in `Filter.rule`:
  `{"lists":[ids],"tags":[names],"priorities":[ints],"due":"today|tomorrow|next7|overdue|nodate|any","keyword":"…"}`.
  Fields combine with AND; values inside a field combine with OR. Unknown keys are ignored (forward
  compatible).
- UI rules follow `feedback-zentask-ui-size`: large rows, targets of at least 44 pt, keyboard first,
  light and dark both checked.

## Rulings made while planning

- **View options:**
  - Options are synced per list as `Preference` records:
    - id `view.<projectId|smart key>`
    - value `{"sort":"date|priority|title|manual","group":"date|priority|list|tag|none","showCompleted":bool}`
  - Default: `manual` + `none` for lists; `date` + `date` for smart lists.
- **Columns:** created, renamed and deleted from the section header menu. Deleting a column moves its
  tasks to "No section"; it never deletes tasks.
- **Drag and drop:**
  - A task onto a sidebar list moves it.
  - A task within the list reorders it, and also changes column when dropped into another section.
  - A list within the sidebar reorders it, or moves it into or out of a folder.
- **Archived lists** get a sidebar section "Archived" (collapsed). This answers the P3 review's
  "nowhere to browse archived lists".

## Review Focus

1. Trashing a list and then restoring it brings back exactly the tasks trashed with it. Tasks trashed
   earlier on their own stay in Trash.
2. Reordering under concurrent edits from another device: two devices moving different items must not
   lose either move. A gap renumbering touches only `sortOrder`.
3. A filter rule with unknown keys or bad values must not crash; it shows "No tasks" and an edit hint.
4. Inbox protections hold in both the UI and `ListActions`.
5. Drag payloads that reference deleted or trashed records are ignored safely.

### Task 1: ListActions + sort-order helpers (shared)

- Create `ListActions`:
  - `createList(name, color?, groupId?)`, `rename`, `setColor`, `archive`/`unarchive`, `trash` (list + its
    tasks, same timestamp), `restore`, `deleteForever` (only from Trash, cascades tombstones to the tasks
    and items trashed with it), `move(listId, groupId?)`;
  - `createFolder`, `renameFolder`, `deleteFolder` (lists inside move to the top level);
  - `createColumn`, `renameColumn`, `deleteColumn` (tasks move to no column), `reorder(entity, id, before?, after?)`.
- Create `SortOrder` with `between(a: Long?, b: Long?): Long?` (null = no gap) and `renumber(ids)`.
- Tests:
  - every action
  - the Inbox protections
  - trash/restore set semantics (Focus 1)
  - gap exhaustion triggering a renumber
  - concurrent reorder on two stores through `applyRemote`
- Commit `feat(lists): list, folder and column actions with sort orders`.

### Task 2: Filters and view options (shared)

- Create `FilterRule` (tolerant decode), `FilterEngine.matches(task, rule, now, zone)`, and
  `TaskFilter.Custom(id)` support in `TaskIndex`, including counts and sections.
- Create `ViewOptions` (decode/encode a Preference) and apply sort and group in `TaskIndex.sections`.
- Tests:
  - every rule field, the AND/OR semantics
  - unknown keys, a bad JSON rule → matches nothing
  - sort by priority/title/manual, group by priority/list/tag
  - preference round trip
- Commit `feat(lists): custom smart lists and per-list sort/group`.

### Task 3: macOS list management UI

- Sidebar:
  - a "+" button on Lists, with "New list" and "New folder" sheets (name, colour palette, folder);
  - context menus on lists (Rename, Colour, Move to folder, Archive, Move to Trash) and on folders;
  - an Archived section;
  - a Filters section, with a "New smart list" sheet (multi-pick lists/tags/priorities, due chips, keyword).
- List toolbar: a sort/group menu and a show-completed toggle.
- Section header menu in lists: Add section, Rename, Delete section.
- Trash smart list shows trashed lists too, with Restore and Delete permanently.
- Tests:
  - `ListUITests`-style model tests (create/rename/archive via the model)
  - snapshots (sheets, menus, archived section) and `design-check`
- Commit `feat(macos): manage lists, folders, sections and smart lists`.

### Task 4: Drag and drop

- `TaskRowView.draggable(TaskDrag(id))` with a `Transferable` that uses a custom UTType
  `com.vuhpquang.zentask.task`.
- Drop on sidebar lists (move), between rows (reorder + column), and lists on lists/folders.
- Tests: the model-level `dropTask(id, onto:)` / `reorder` logic, plus a snapshot of the drop highlight.
- Commit `feat(macos): drag and drop for tasks and lists`.
